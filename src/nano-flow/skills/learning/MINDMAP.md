# Mindmap

导图笔记给骨架：一张导图 = 一个主题的全部节点，节点是标题，父子即层级。读者点节点看概述与引用，导图只读。

材料分得出层级、读者先要全貌时写导图；要闭卷复述细节按知识型，要照抄代码按使用型（[RULE.md](RULE.md)）。导图与正文笔记并存，同一解释只在一处写全。

## 1. 放位置

导图是普通 wiki 文档，放 `docs/` 下任意目录，与正文笔记同级。frontmatter 用 `id` 与 `anki`；写了 `id`，别的笔记才能用 `doc:<id>` 指向它。导图不给复习点，写 `anki: false`，卡片落在正文笔记上。

## 2. 排节点

`<Mindmap>` 标签内是普通 markdown。标题开头写数字编号，编号即节点 id：

```markdown
<Mindmap>

# 1 TypeScript

## 1.1 基础数据类型

### 1.1.1 如何为基础类型标注？

## 1.2 接口

</Mindmap>
```

构建期拦这些：根不唯一（必须有且只有一个 `#`）、标题缺编号、层级跳级、编号同图重复、节点引用指向不存在的编号。编号续写父前缀（`1` → `1.1` → `1.1.1`）是阅读约定，不校验。

## 3. 填概述与引用

标题下的普通段落是概述，浮窗逐行显示；代码块与列表不进浮窗。引用写在 `>` 引用块里，一条一行：

```markdown
> - [基础数据类型](010-基础数据类型.md) doc:07b40046-e58e-4b78-a552-928d99eb18fb
> - [接口](#1.2)
```

- `doc:<文档id>`：打开该文档的 `/<id>` 短链，新标签页。解析只认 `doc:` 后的 id，链接路径不参与跳转；id 写错不拦构建，只在点击时 404，落笔前核对目标文档的 frontmatter `id`；
- `#<编号>`：关浮窗并跳到本图节点，编号不存在构建期报错。

## 4. 验收

导图打开时根居中、子节点分列两侧；点节点浮窗贴节点出现，滚轮缩放、拖动平移可用；全屏里看节点数、引用数与缩放读数。

```bash
pnpm --filter @kxh4892636/wiki start   # 单页编译失败会直接报错；构建用 build
```

单图几十到几百节点；过千先按子主题拆图。

## 模板

```markdown
---
id: <uuid>
anki: false
---

# <主题>

一句话说明这张图讲什么。

<Mindmap>

# 1 <主题>

一句话概括。

## 1.1 <子主题>

概述一行。

> - [<标签>](<相对路径>.md) doc:<目标文档id>
> - [<标签>](#1.1.1)

### 1.1.1 <子子主题>

概述一行。

</Mindmap>
```
